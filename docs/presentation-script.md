## 01. AWS 기반 팀 공유 AI 개발환경 구축 및 운영 (00:00–00:20)

안녕하세요. 김건보, 강태영, 박찬욱 팀입니다. 기존 Orca를 AWS EC2 한 대에 배포하고, 팀 운영 포털을 직접 구현했습니다.

근거: README.md, STATUS.md

## 02. 기존 Orca 위에 팀 운영 포털을 만들었습니다 (00:20–01:00)

여럿이 같은 서버의 개발환경을 쓰면 누가 무엇을 했는지, 서버가 정상인지 확인하기 어렵습니다. 그래서 기존 Orca를 편집 도구로 쓰고, 프로젝트·메모·첨부와 점검·복구 기능을 담은 포털을 직접 만들었습니다. 새 IDE나 에이전트 엔진을 만들었다고 하지 않습니다.

근거: AGENTS.md, README.md, docs/contributions.md

## 03. 공개 HTTPS와 비공개 데이터를 분리했습니다 (01:00–01:40)

외부 접속은 도메인과 고정 IP로 Nginx HTTPS가 받습니다. 포털은 서버 내부에서 실행하고 Orca와 Webmin은 포털 인증을 거칩니다. DB는 비공개 RDS, 파일은 비공개 S3이고, Orca와 Webmin 포트는 직접 공개하지 않습니다.

근거: docs/architecture.md, deploy/

## 04. Python 웹 애플리케이션과 관리형 DB를 사용했습니다 (01:40–02:05)

Ubuntu 24.04 EC2에서 Python 3.12와 FastAPI로 API를 만들고, SQLAlchemy로 RDS MySQL에 연결했습니다. 화면은 단순 HTML·CSS·JavaScript입니다.

근거: requirements.lock, docs/deployment.md

## 05. 계정·세션·차단 상태를 별도로 저장합니다 (02:05–02:35)

한 사용자는 여러 세션을 가지며, 차단 상태는 별도 테이블에 둡니다. 세션에는 토큰 원문 대신 해시와 만료, CSRF 값을 저장합니다. 운영 이벤트는 점검·백업 이력을 담는 독립 테이블입니다.

근거: app/models.py, docs/data-model.md

## 06. 프로젝트를 기준으로 메모·첨부·Orca를 연결합니다 (02:35–03:05)

프로젝트 하나에 메모와 첨부가 여러 개 연결되고, Orca 연결은 없거나 하나입니다. 첨부 파일 본문은 S3에, 정보는 DB에 둡니다. Orca 내부 DB는 포함하지 않습니다.

근거: app/models.py, app/storage.py, docs/data-model.md

## 07. 채팅과 Orca 연결 요청도 DB에 저장합니다 (03:05–03:35)

근거: app/models.py, app/collab.py, app/orca_admin.py, docs/data-model.md

## 08. 그룹·활동·보관 정보는 별도 테이블로 더했습니다 (03:35–04:00)

그룹과 그룹 멤버, 마지막 로그인과 첫 로그인 비밀번호 변경 여부, 프로젝트 보관과 메모 수정 기록을 각각 별도 테이블로 두었습니다. 운영 중인 기존 테이블은 바꾸지 않아 배포가 안전합니다.

## 예상 질문과 답변

**Orca를 직접 개발했나요?** 기존 Orca를 배포했다. 직접 구현한 부분은 FastAPI 운영 포털, 인증·역할·연결 회수, 데이터 관리와 운영 자동화다. AI 도구의 코드 작성 지원을 받았다.

**실제 AI 요청도 성공했나요?** 서버용 AI 로그인은 보류 중이다. 실제로 검증한 것은 원격 파일 편집·저장과 터미널 실행이다.

**왜 EC2가 한 대인가요?** 과제 범위를 한 대로 정했다. ALB의 2개 AZ 사용이 단일 앱 서버의 고가용성을 뜻하지 않는다.

**Route 53도 사용했나요?** 기존 무료 DNS로 도메인을 연결했다. 유료 Route 53 호스팅 영역은 만들지 않았다.

**왜 CloudFront를 삭제했나요?** 승인된 시연 기간에 별도 정적 안내 페이지를 실제 검증한 뒤 비용을 관리하기 위해 삭제했다. 현재 제공되는 포털 프런트는 EC2의 같은 출처다.

**백업을 만들기만 했나요?** RDS 논리 데이터는 별도 SQLite·폴더에 복원했고, 코드도 빈 폴더에 복원해 내용 일치를 확인했다. 새 RDS 스냅샷/PITR 또는 서버 전체 복원은 시험하지 않았다.

**세 명이 완전히 격리되나요?** 포털 역할은 구분하지만 Orca는 공유 런타임이다. 사용자별 프로세스·파일 격리나 동시 편집 충돌 해결을 제공한다고 주장하지 않는다.

**0.02초는 성능 보장인가요?** 공개 WebSocket 한 시험 세션에서 관측한 로그아웃 후 종료 시간이다. 다수 사용자·고부하 성능 지표가 아니다.

**중지하면 과금이 없어지나요?** EBS, RDS 저장소, EIP와 S3 저장 비용은 남는다. RDS는 중지 후 최대 7일 뒤 자동 재시작할 수 있다.

**왜 접속이 안 될 때가 있나요?** 승인된 운영 창 밖에서는 서버를 중지한다. 고정 IP는 주소를 유지할 뿐 중지된 서버를 실행하지 않는다.
