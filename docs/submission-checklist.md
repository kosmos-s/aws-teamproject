# 제출 점검표

## 준비한 산출물

- 공지 기준 23장 PowerPoint와 발표용 PDF. 편집은 PPTX에서 하고 PDF는 열람용으로 사용한다.
- 발표 대본과 슬라이드별 근거, 예상 질문 답변.
- 실제 소스·테스트·배포 설정·운영 문서의 소스 ZIP과 파일별 SHA-256 목록.
- 팀원 3인 시연 준비와 실제 결과 기록 양식.

## 제출 전 직접 확인

- 교수자가 정한 제출 형식, 마감, 파일명, 발표 시간을 실제 공지와 대조한다. 이 묶음은 채점 조건 충족을 보장하지 않는다.
- PowerPoint에서 PPTX를 열고 글꼴·한글·화살표·표·발표자 노트를 확인한다. 생성기의 이미지 검사와 구조 검증은 실제 PowerPoint 실행 검증을 대신하지 않는다.
- 팀원 이름은 김건보, 강태영, 박찬욱이다. 학번·분반은 제공받지 않아 작성하지 않았다. 팀명은 없다.
- 실제 참여 기록을 바탕으로 개인별 기여를 작성한다. AI 도구의 작성 지원과 기존 Orca/Webmin 활용 범위를 구분한다.
- AI 실제 요청·3인 동시 접속·메일 실제 발송·TOTP 등록·RDS 스냅샷 복원은 수행한 경우에만 완료로 바꾼다.
- 제출물에 비밀번호, AWS 키/계정 ID/세션, 페어링 링크, 운영 DB, 백업, .local, .git, 원본 강의 PDF를 넣지 않는다.
- 삭제된 ALB/CloudFront 시연 주소를 현재 접속 주소로 안내하지 않는다. 현재 운영 상태와 종료 시각은 STATUS.md를 확인한다.
- RDS는 중지 후 최대 7일 뒤 재시작될 수 있다. 과제 종료 후 보존/최종 삭제 범위는 별도 결정한다.

## 소스 재현

Python 3.12 이상에서 가상환경을 만들고 requirements.lock을 설치한 뒤 `python -m unittest discover -s tests -v`를 실행한다. 운영 환경값은 .env.example을 참고해 별도로 제공한다. 소스 ZIP만으로 AWS에 자동 배포되지는 않는다. 기존 자원을 조회하지 않고 초기 provision 스크립트를 반복 실행하지 않는다.

ZIP은 Git 추적 파일과 이번 제출용 문서만 명시적으로 포함했다. 최신 앱 소스의 자동 테스트는 이전 검증 기록을 따르며, 이번 발표·문서 작업에서는 앱 동작을 변경하지 않았다.

이전 v2는 23장(설명 13:45, 시연·전환 6:15)이었다. v5(20장, 설명 10:15 + 시연 6분)가 최신이다. v5에 팀 채팅·멤버 관리·Orca 연결·Webmin 장표와 협업 ERD를 추가했다(화면은 로컬 데모 캡처, Webmin 캡처 자리 비어 있음). v3에 역할·발표자(박찬욱)를 반영했고 v4에서 ERD를 열·타입·PK/FK/UK와 행 단위 관계선으로 개선했다. 원본 과제 공지 자체는 제출 ZIP에 포함하지 않는다.
