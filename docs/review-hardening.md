# 보안·운영 개선과 팀 변경사항

검토 기준 main: `4552706`. 이 문서는 로컬 구현을 설명하며 운영 반영 완료 증거는 별도 배포 기록을 따른다.

## 달라진 동작

- 프로젝트 공개 상태를 `project_policies`에 따로 보관한다. 마지막 허용 그룹을 지워도 제한 공개가 유지된다. 관리자는 전체 회원 공개를 명시적으로 선택할 수 있다.
- 삭제한 채팅 사진은 즉시 접근 불가다. 실제 저장소 삭제 실패는 `object_deletions`에 남기고 기존 점검 타이머에서 재시도한다.
- TOTP 설정과 관리자 초기화에 현재 비밀번호를 요구한다. 설정·활성화·해제·초기화는 계정별 5회/5분 제한을 공유한다. 비밀값은 Fernet으로 암호화하고, DB 밖 서비스 전용 키 파일을 사용한다. 복구 코드는 8개를 한 번만 표시하고 해시로 저장한다.
- HTTP와 Orca는 만료·차단·유휴 상태·비밀번호 변경 요구를 검사한다. 유휴 활동 시각은 DB에 저장하며 화면의 자동 조회는 활동으로 계산하지 않는다. 키보드·마우스 등 실제 포털 활동만 30초 간격으로 전달한다.
- 채팅 증분 조회는 오래된 미수신 메시지부터 받는다. 읽음·수정 정보 재조회 전에도 이전 커서 이후 메시지를 먼저 모두 받는다. 홈/숨긴 탭의 수신은 읽음으로 계산하지 않고 채팅 진입 시 표시된 마지막 메시지를 확인 처리한다.
- 읽음 위치는 MySQL/SQLite의 원자적 upsert로 최댓값만 저장한다. 로그인과 반응 토글·업로드·도배 제한은 단일 worker 내부의 동시 요청을 보호한다.
- 방별 사용자 대상 알림과 이벤트 대기를 사용한다. 사용자별 읽음·미확인 수 조회를 집계하고 채팅 복합 인덱스를 추가했다. worker 증설은 이 설계의 전제가 아니므로 하지 않는다.

## 대시보드 팀 변경사항

프로젝트·메모·할 일·첨부 변경을 DB에 남겨 다음 날 접속해도 볼 수 있다. 프로젝트 이름·변경 종류·작업자·시각과 이동 버튼을 표시한다. 목록은 20개씩 조회하고 이전 내역을 더 볼 수 있다. `모두 확인`은 현재 조회 시점까지의 알림을 계정별로 확인 처리한다.

관리자는 전체 공지를 작성할 수 있다. 계정·팀 운영 설정 변경은 관리자용 알림이며, 프로젝트 변경은 조회 시점의 현재 프로젝트 권한을 적용한다. 메모 원문·비밀번호·TOTP 키·페어링 정보는 공통 알림에 넣지 않는다. 채팅 메시지는 기존 채팅 알림에서 처리한다.

## 알림·용량·진단

- 내 계정에서 전체/멘션만/끄기와 소리를 계정별로 저장한다. 브라우저 시스템 알림 허용 여부는 브라우저 설정과 별개다.
- 기본 활성 파일 한도: 사용자 20MiB, 프로젝트/채팅방 40MiB, 전체 100MiB. 환경 변수 `UPLOAD_USER_MIB`, `UPLOAD_SCOPE_MIB`, `UPLOAD_TOTAL_MIB`으로 운영자가 조정한다. 기존 파일도 시작 시 집계한다. 업로더를 알 수 없는 기존 첨부는 `(legacy)`로 집계한다. 기존 프로필 사진은 보수적으로 512KiB를 계산한다.
- 실패한 실제 S3 삭제는 진단 자료에 남는다. 활성 파일 한도와 S3 청구 용량은 같다고 가정하지 않는다.
- `CHAT_RETENTION_DAYS=0` 기본값은 자동 채팅 삭제 비활성이다. 운영자가 양수로 명시한 경우 고정 점검 작업에서 오래된 메시지와 파일을 묶어서 정리한다. 고정 공지는 보존한다.
- 서버 오류에는 문의 번호를 표시한다. 관리자 진단 다운로드는 테이블별 개수·대기 삭제 수 등 허용한 집계만 포함한다. 환경·DB 주소·사용자 이름·본문·토큰은 포함하지 않는다.

## 백업 v3

그룹·멤버 관계·공개 상태·할 일·프로필·파일·팀 변경사항·읽음 상태를 포함한다. 메인/그룹 채팅을 포함하며 기존 정책대로 개인 DM과 관련 첨부는 제외한다. 계정 ID/이름/역할 매핑을 저장해 관계를 보존하되 비밀번호 해시·세션·TOTP·복구 코드는 저장하지 않는다. 복구 계정은 무작위 미공개 비밀번호와 차단 상태로 생성한다.

복구 운영자는 별도 새 복구 관리자 계정을 CLI로 생성하고, 실제 소유자를 확인한 뒤 계정 재설정·차단 해제를 수행한다. 기존 이름과 같은 계정을 중복 생성하지 않는다. Orca의 사용자 파일과 AI 계정은 포털 논리 백업 범위 밖이며 코드 백업/EBS 복구와 구분한다.

이전 v1/v2도 읽을 수 있지만 ACL 정보가 없는 구형 복구 프로젝트는 제한 공개로 시작한다. 모든 복구는 빈 대상 DB와 별도 저장 폴더에서 시험한다. 16MiB/테이블당 10,000행의 과제 한도는 유지한다. 이를 초과하면 성공으로 위장하지 않고 실패한다.

## 배포·롤백 주의

새 테이블과 인덱스를 추가하며 기존 테이블을 파괴적으로 변경하지 않는다. 최초 시작 시 기존 ACL과 파일 사용량을 이전하고, 활동 시각이 없는 구형 세션은 새 로그인을 요구한다.

TOTP는 기존 `user_totp.secret`을 `vault` 표식으로 바꾼다. 따라서 이전 코드 파일만 복원하는 롤백은 금지한다. 새 코드/키로 시드를 원래 필드에 복원한 후 구형 코드를 되돌리는 절차가 필요하다. 복호화 값은 출력하지 않는다. `totp.key`는 운영 환경에서 서비스 계정만 읽는 0600 파일이며 Git·논리 백업에 포함하지 않는다. 키 분실 시 TOTP 재등록을 위한 관리자 복구 절차가 필요하다.

서버 배포·main 병합·AWS 변경은 현재 사용자의 별도 확인 후 진행한다. 기존 EC2/RDS 한 대씩만 사용하고 새 유료 서비스를 만들지 않는다. AI 로그인과 새 소유자/Deploy key 기능은 이번 범위에 포함하지 않는다.
