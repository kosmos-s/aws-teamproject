# 외부 AI(ChatGPT 등) 점검 요청 프롬프트

아래 블록을 그대로 복사해 ChatGPT에 붙여 넣는다. 저장소를 읽지 못하는 환경이면 AI가 필요한 파일을 요청하므로, 그 파일 내용을 붙여 준다. 비밀번호·토큰·`.local/` 내용은 절대 붙이지 않는다.

## 짧은 버전 (빠르게 물어볼 때)

```text
너는 시니어 웹 개발자이자 AWS 보안 리뷰어야. 아래 대학 팀 과제를 점검하고 개선점과 추가 기능을 알려줘.

- 저장소(공개): https://github.com/kosmos-s/aws-teamproject (main 브랜치)
- 주제: AWS EC2 한 대에 Orca(원격 개발환경)를 올리고, 팀 운영 포털을 직접 만든 프로젝트
- 구성: FastAPI + SQLAlchemy + 순수 HTML/JS, 비공개 RDS MySQL, 비공개 S3, Nginx HTTPS, uvicorn 1 worker
- 주요 기능: 역할·그룹·공개 범위, 팀 채팅(롱 폴링, 멘션, 사진, 읽음 숫자, 도배 방지), 할 일 보드, 2단계 인증, 자동 로그아웃, 점검·백업·복원, 관리자 Orca 연결
- 제약: EC2는 한 대, 새 유료 서비스는 비용과 함께 제안, 웹 입력을 셸 명령으로 실행하지 않음

점검 항목: 보안 / 버그·동시성 / 성능(수십~수백 명) / 운영·비용 / UX / 과제 평가에서 감점될 부분 / 추가 기능

답변 형식:
1. 3줄 요약
2. 표: 우선순위(P0 즉시 · P1 발표 전 · P2 여유) | 문제·제안 | 근거(파일 또는 관찰) | 해결 방법
3. 발표 전에 꼭 할 5가지
저장소를 직접 못 읽으면 그렇다고 말하고, 필요한 파일 목록을 요청해 줘. 한국어로 답해.
```

## 상세 버전


```text
너는 시니어 웹 개발자이자 AWS 운영·보안 리뷰어다. 대학 클라우드 컴퓨팅 3인 팀 과제를 점검하고, 개선점과 추가 기능을 우선순위대로 제안해 줘.

## 프로젝트
- 주제: AWS 기반 팀 공유 AI 개발환경 구축 및 운영
- 저장소(공개): https://github.com/kosmos-s/aws-teamproject  (main + PR #3 브랜치 feat/chat-alarm-single-session)
- 구성: EC2 한 대(Ubuntu 24.04, t3.small) + 고정 EIP + Nginx HTTPS
  - 운영 포털: Python 3.12 / FastAPI / SQLAlchemy, 단순 HTML·CSS·JS (프레임워크 없음), uvicorn 1 worker
  - DB: 비공개 RDS MySQL 8.4 (EC2 SG에서만 접근), 테스트는 SQLite
  - 파일: 비공개 S3 (EC2 역할은 attachments/·backups/ Get/Put만)
  - 기존 도구: Orca 1.4.255(원격 개발환경, 포털 인증 뒤에서 접속), Webmin(관리자 전용)
  - 서버 AI: Codex CLI, Claude Code 설치(로그인은 사용자가 직접)
- 포털 기능: 로그인·역할(admin/member/viewer), 한 아이디 한 곳 접속, 첫 로그인 비밀번호 변경, 여러 명 초대, 그룹, 프로젝트(보관·그룹별 공개 범위), 작업 메모(수정·삭제), 첨부(1MiB, 삭제), 팀 채팅(전체·그룹·1:1, 롱 폴링, 읽음 숫자, 전송 실패·재전송, 알람), 활동 기록, 점검·백업 이력, 관리자 Orca 연결 요청(웹은 요청만 기록, root 타이머 워커가 고정 단계만 실행), 다크·라이트 모드, 모바일 대응
- 운영: 승인된 시간에만 EC2/RDS 가동, AWS Scheduler + 서버 타이머로 자동 중지, 매분 점검, 매일 논리 백업(S3), RDS 스냅샷 복원 시험 완료
- 테스트: unittest 78개, GitHub Actions CI
- 문서: README.md, STATUS.md, AGENTS.md, docs/(architecture, deployment, verification, costs, data-model, user-guide)

## 지켜야 할 제약 (이 범위를 벗어나는 제안은 '범위 밖'으로 따로 표시)
- EC2는 한 대만. 새 유료 서비스·상시 비용 증가는 비용과 함께 제시
- 새 웹 IDE, CRDT 공동 편집기, 자체 에이전트 엔진, 사용자별 컨테이너는 만들지 않음
- 웹 입력을 셸 명령으로 실행하는 API 금지. 비밀정보는 Git에 넣지 않음
- 운영 중인 DB 테이블은 ALTER 대신 새 테이블로 확장해 왔음

## 점검해 줄 것
1. 보안: 인증·세션·CSRF·권한 우회, 그룹 공개 범위 누수, 파일 업로드·다운로드, 로그/에러에 비밀정보 노출, Orca·Webmin 노출, IAM 최소권한
2. 정확성·버그: 동시성(채팅·세션), 롱 폴링, 실패 처리, 백업·복원, 워커 처리 흐름
3. 성능·확장성: 1 worker + 폴링/롱 폴링 구조의 한계, 멤버 수가 수십~수백 명일 때 병목, DB 쿼리
4. 운영·비용: 자동 중지, 모니터링, 장애 대응, 인증서 갱신, 로그 보관
5. UX: 처음 쓰는 사람 기준 화면 흐름, 모바일, 접근성
6. 과제 평가 관점: 발표 자료·기능 설명, 기술 설명(ERD·아키텍처), 소스 완성도, 팀 역할, AI 활용 근거에서 점수가 깎일 만한 부분
7. 추가하면 좋은 기능 (동아리·회사에서 실제로 쓸 때 기준)
```
