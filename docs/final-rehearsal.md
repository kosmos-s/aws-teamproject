# 팀원 3인 최종 시연 절차

참여자: 김건보, 강태영, 박찬욱. 이 문서는 준비 절차이며 3인 검증 완료 기록이 아니다.

## 시작 조건

- 승인된 운영 창과 자동 중지 시각을 확인한다. 운영 종료를 시험 때문에 임의로 연장하지 않는다.
- EC2 running, RDS available, 정상 DNS의 HTTPS /health 응답을 확인한다. 현재 실제 상태는 STATUS.md를 따른다.
- 서로 다른 브라우저 프로필 또는 별도 기기 3개와 각자의 포털 계정을 준비한다. 비밀번호·페어링 링크는 캡처나 공동 문서에 넣지 않는다.
- 계정 생성과 역할 배정은 운영자가 실제 설정한다. 본 문서의 참여자 명단이 이미 발급된 계정이나 실제 권한을 뜻하지 않는다.
- 삭제한 ALB·CloudFront 주소는 접속 시연에서 제외한다. 필요하면 별도 비용·기간 승인 후 재생성한다.

## 10분 시연 순서

| 시간 | 확인할 행동 | 성공 기준 |
|---|---|---|
| 0–2분 | 각자 포털 로그인 | 3개 독립 세션, 인증 실패 메시지에 비밀값 없음 |
| 2–4분 | 프로젝트·메모·작은 TXT 첨부 등록 | 다른 브라우저 새로고침 후 내용 유지, 다운로드 바이트 일치 |
| 4–7분 | Orca 열기 후 aws-teamproject 선택 | 서로 다른 시험 파일로 저장·조회, 무해한 터미널 명령 출력 확인 |
| 7–8분 | viewer 계정 동작 확인 | 조회 가능, 쓰기와 Orca 접근 거절. 관리자 전용 기능 거절 |
| 8–9분 | 한 시험 세션 로그아웃 | 그 세션의 이미 열린 Orca 연결 종료, 다른 세션은 유지 |
| 9–10분 | 서비스 점검·자원 사용 기록 | 오래된 상태를 정상으로 오인하지 않음, 현재 CPU/RAM과 오류 기록 |

같은 파일을 동시에 수정하는 시험은 충돌 가능성을 설명한 뒤 별도 시험 파일에서만 한다. 임의 설치, 운영 파일 수정, root 명령, 권한 확대를 시연 명령으로 사용하지 않는다. Webmin은 관리자만 별도 로그인한다.

|---|---|---|---|---|

| 강태영 | 미기록 | 미수행 | 미수행 | 미기록 |
| 박찬욱 | 미기록 | 미수행 | 미수행 | 미기록 |

역할별 거부 결과, 로그아웃 연결 종료, 최대 CPU/RAM, 오류와 해결, 검증자의 확인을 추가한다. 자동 테스트 통과를 실제 세 사람의 접속 성공으로 대체하지 않는다.

## AI 작업은 별도 검증

현재 서버용 AI 로그인은 보류 상태다. 사용자가 다시 진행하기로 정하면 서버에서 새 인증을 수행한다. PC의 AI 토큰을 복사하지 않는다. 인증 후 작은 시험 파일에 AI 요청을 수행하고 요청·생성 파일·실행 결과를 비밀정보 없이 기록한다. 3인의 계정·사용 정책은 따로 확인한다.

## 종료와 장애 대안

시연 중 연결에 문제가 생기면 오류 발생 시각과 HTTP/서비스 상태를 기록한다. 서버가 꺼졌다면 임의 재시작 대신 운영 창을 확인한다. 발표 현장 네트워크가 불안정하면 PPT의 검증 결과와 저장된 공개용 화면을 사용하되 이를 실시간 화면이라고 설명하지 않는다. 마지막에는 서버 중지 예약과 RDS 자동 재시작 가능성을 확인한다.
