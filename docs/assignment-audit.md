# 과제 공지 원문 대비 점검

검토일: 2026-11-11 KST. 사용자가 제공한 **클라우드 컴퓨팅 팀별 과제_OOO팀_공지 (1).pptx** 4장을 텍스트와 렌더링 화면으로 확인했다. 원본은 수정·저장소 포함하지 않았다. 공지 문구는 평가 기준으로 사용하며 실습 명령을 실행 승인으로 해석하지 않는다.

## 판단

주제와 실제 AWS 배포 방향은 공지와 맞는다. EC2 한 대, 자체 포털/API, 비공개 RDS·S3, 공개 URL, GitHub·CI와 실제 복구 검증 근거가 있다. 다만 **현재 자료를 그대로 완성 제출본으로 판단하기는 어렵다.** 팀별 역할·참여 근거, AI 활용의 실제 범위, ERD·기술 사양·배포 명령의 발표 표현과 20분 시연 구성이 더 필요하다. 아래 표는 예상 점수가 아니라 확보한 근거와 남은 공백이다.

## 원문의 명시 조건

- 1장: 자유 주제 애플리케이션 개발 및 클라우드 컴퓨팅 적용. 팀 편성은 4명 내외로 안내한다. 현재 실제 명단은 김건보·강태영·박찬욱 3명이다. 문구만으로 정확히 4명이 필수이거나 3명이 승인됐다고 단정할 수 없다.
- 2장: Route 53은 생략 가능, EC2는 1개만 사용. 개발 언어는 HTML/JSP/Python/Java/C/기타가 가능하다. AI의 개발·적용 방법, 설치·GitHub·빌드, URL로 확인한 AWS 적용 결과를 설명한다.
- 1장: 팀별 발표는 20분 내외이며 실행 결과 시연 또는 필요한 영상 등을 활용한다. 제출물은 PPT·소스/이미지다. 마감·발표 날짜는 O/OO 등 예시 표기라 이 파일로 실제 날짜를 확정할 수 없다.
- 2장의 그림은 AWS 아키텍처 예시다. 이 그림에 여러 EC2가 보이더라도 하단의 EC2 1개 조건을 따른다. 모든 서비스의 상시 운영이 필수라고 쓰여 있지는 않다. 현재 ALB/CloudFront는 별도 한시 시연임을 표시한다.

## 특히 분리해서 설명할 것

**AI 활용:** AI 도구의 개발 지원은 실제 사용 사실로 설명할 수 있다. 서버의 Codex Agent 로그인과 실제 AI 작업은 아직 보류·미검증이다. 공지가 별도 AI API/RAG를 반드시 새로 개발하라고 단정할 근거는 없지만, 프로젝트 제목의 AI 개발환경을 시연하려면 실제 작은 AI 작업까지 검증하는 편이 설득력 있다. 현재 상태에서 이를 성공한 기능으로 발표하면 안 된다.

**배포와 정리:** 핵심 포털·Orca는 EC2 한 대에서 공개 HTTPS로 검증했다. ALB는 /health 시연, CloudFront는 별도 정적 안내 페이지로 검증 후 삭제했다. 이를 현재 모든 사용자 트래픽이 ALB/CloudFront를 통과하는 구조로 그리지 않는다. 고가용성·사용자별 격리도 주장하지 않는다.

**복구:** 업무 데이터는 별도 SQLite/폴더에 논리 복원했고 코드도 별도 폴더에 복원했다. RDS 스냅샷/PITR로 새 운영 RDS를 만드는 시험이나 서버 전체 이미지 복구와 구분한다.

**팀 참여:** 실제 역할을 임의 배정해 과거 기여처럼 작성하지 않는다. 세 사람이 각자 맡아 검토·실행·설명할 항목을 정하고 그 이후의 결과를 기록한다. 3인 구성 허용 여부와 실마감은 담당 교수/실제 공지에서 확인할 사항이다.

## 우선순위

1. 완료: 새 23장 PPT에 [ERD](data-model.md) 2장, 기술 사양과 배포·실행 명령, 교훈을 추가했다.
2. 세 사람의 실제 역할·기여·발표 구간을 확정하고 커밋·검토·시연 근거를 남긴다.
3. 허용된 운영 시간 안에 [3인 시연](final-rehearsal.md)을 수행하고, 사용자가 AI 로그인을 재개하기로 결정하면 서버에서 새 인증 후 실제 AI 작업을 검증한다.
4. 20분을 재며 연습하고, 제출 형식·실마감·3인 구성 여부를 최종 확인한다.

검토 근거: AGENTS.md, STATUS.md, app/models.py, app/main.py, app/ops.py, requirements.lock, .github/workflows/tests.yml, docs/course-demo.md, docs/verification.md, docs/contributions.md 및 실제 제출 PPTX/ZIP 검증 기록. 이는 채점 확약이나 포괄적 보안 감사가 아니다.
